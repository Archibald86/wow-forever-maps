# Агент-аудитор сайта

Агент находится в [GitHub Actions → Atlas AI auditor](https://github.com/Archibald86/wow-forever-maps/actions/workflows/site-auditor.yml). Запуск — ежедневно в 06:00 по Москве, вручную кнопкой **Run workflow**, а также при изменении его кода. Расписание GitHub может выполняться с задержкой.

## Что он делает

1. Проверяет публичные страницы Zephras, ForeverChanges и Wowhead, включая RSS Wowhead. Сохраняет отпечатки страниц, чтобы различать первый снимок, реальные изменения и неизменившиеся страницы.
2. Сверяет явно указанные уровни, типы и координаты NPC с нашим слоем Classic. Отдельно учитывает версию игры, сборку и дату наблюдения. Одиночный уровень внутри исходного диапазона не объявляется ошибкой. Число наблюдений не превращается в число мобов.
3. Проверяет структуру локальной базы, уникальность GUID и связи ограничений. Запускает воспроизводимые сборки, Python/JS-тесты и браузерные проверки всех 40 карт, цветов, фильтров и настроек.
4. Если настроен OpenAI API, передаёт модели ограниченный набор фактов, изменений и ошибок. Получает рекомендации со ссылками на существующие доказательства. Неполный ответ и выдуманные ссылки отклоняются.
5. Сохраняет `report.md` и `report.json` в сводке запуска и артефакте `atlas-audit-N` на 30 дней. Код и данные сайта запуском агента не изменяются.

Найденные расхождения — кандидаты для проверки. Отсутствие расхождений в выборке не доказывает полноту базы. Агент не измеряет текущую плотность сервера, не считает патрульные координаты новыми мобами и не подтверждает Forever по совпадению двух Classic-источников.

## Включить ИИ

Откройте [Settings → Secrets and variables → Actions](https://github.com/Archibald86/wow-forever-maps/settings/secrets/actions) → **New repository secret**:

- Name: `OPENAI_API_KEY`
- Secret: ключ вашего проекта OpenAI API.

Ключ не нужно присылать в чат или сохранять в файлах проекта. Интеграция GitHub, использованная для разработки, не предоставляет управление секретами; этот шаг выполняет владелец репозитория. До добавления ключа сбор, сравнение и тесты работают, а в отчёте явно указан статус `not_configured`. Подписка ChatGPT сама по себе не настраивает доступ этого workflow к API.

После добавления ключа запустите **Run workflow** с включённым `ai`. Для повторного разбора уже просмотренных данных включите `force_ai`. Без изменений повторного запроса к модели нет. При ошибке API детерминированный отчёт сохраняется; повторный ИИ-разбор можно запросить вручную, автоматических повторов внутри запуска нет.

Модель по умолчанию — `gpt-4.1-mini`. При необходимости её можно изменить переменной репозитория `AI_AUDITOR_MODEL`. Модель получает данные через OpenAI Responses API с `store=false`; это не обещание отсутствия иных сроков хранения у поставщика API. Документация: [модель и тарифы](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [структурированный ответ](https://developers.openai.com/api/docs/guides/structured-outputs).

## Ограничения расходов и охвата

Настройки — [audit/config.json](audit/config.json):

- Максимум один запрос к ИИ за запуск, без повторов и инструментов модели.
- Вход ограничен бюджетом 20 000 UTF-8-байт с резервом под инструкции/схему; ответ — максимум 2 000 токенов. Фактическое использование токенов записывается в JSON-отчёт. Это ограничение запросов и объёма, не гарантия фиксированной долларовой цены; тариф зависит от выбранной модели. Для контроля оплаты настройте бюджет/лимиты проекта у поставщика API.
- До 56 сетевых запросов, 4 МБ на ответ и 20 МБ загрузки за запуск, пауза минимум 1 секунда между запросами к одному хосту.
- Четыре контрольных NPC и 16 следующих по очереди, плюс ограниченное обнаружение новых ссылок. Все 2 366 видов не проверяются ежедневно; список проверенных ID и фактический охват находятся в отчёте.
- Соблюдаются `robots.txt` и задержки обхода. При 401/403/429 дальнейшие запросы к хосту прекращаются. Агент не использует обход блокировок, скрытые API, чужие сессии или смену личности браузера.
- Wowhead и другие сайты могут выдавать только часть сведений без JavaScript. `metadata_only` не считается подтверждением уровней или координат; запрет/ошибка доступа явно отражается в отчёте. Данные Classic и Forever не смешиваются.

Первая проверка создаёт базовый снимок, а не объявляет все найденные записи новыми изменениями игры. Не проверенная повторно старая проблема не считается исправленной. Старый снимок недоступной страницы сохраняется. Первые найденные различия требуют сверки источников перед изменением сайта.

## Безопасность и данные

У workflow только `contents: read`; он не публикует исправления и не пишет комментарии/письма. Источники и ответ модели — недоверенные данные. Модель не может запускать команды, менять файлы, выбирать адреса с секретами или создавать дополнительные вызовы. Команды тестов заданы в коде; HTML/Markdown отчёта экранируется. Цитаты ограничены короткими фрагментами, сохранены ссылки и факты; полные сторонние страницы не включаются в кэш и артефакты.

Кэш хранит отпечатки страниц, факты, очередь NPC и идентификаторы находок, без API-ключей. Используется отдельный последовательный workflow; PR из внешних веток не запускают его с секретами.

## Локальный запуск

Без сети и модели: `python tools/site_auditor.py --offline --checks --no-ai`.

Сбор сайтов и правила без модели: `python tools/site_auditor.py --checks --no-ai`.

Сбор и ИИ: `python tools/site_auditor.py --checks` при наличии `OPENAI_API_KEY` в окружении. Не вставляйте ключ в командную строку или файлы проекта.

Проверки агента: `python -m unittest discover -s tests -p test_site_auditor.py -v`.

Выходы по умолчанию — `audit-output/`, состояние — `audit-state/`. Эти каталоги не являются исходниками сайта и не должны коммититься. Для воспроизводимых тестов доступен `--fixture-dir`: файл `manifest.json` сопоставляет URL с локальными HTML/RSS-файлами; такой запуск явно отмечается как `fixture`, ИИ не вызывается.
